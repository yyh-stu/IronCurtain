# 大模块任务卡

状态均为待执行；本轮没有委派实施。负责人均为制作人指定的执行编排；代码/资源执行者和独立审核员由其在开工台账中明确。公共接口授权默认“无”；需要变更的按 README §5 送具体契约单。

每个模块继承 README 的全局边界及 03 的门禁，下面仅列差异，避免重复大段上下文。建议子模块数合计25，编号用于交接，不要求一个子模块等于一次模型调用。无须为凑数再拆。每个模块开工都记录任务卡版本/hash、当时完整基线、负责人、预算估计和审核安排。

## M0｜现状、契约与验收基线

目标：执行者能重现最新 Demo，知道哪些效果缺资源、缺事件、缺状态查询或只是缺验收。

依赖：无。工作量参考8%。允许：读取完整工作树；生成文档、清单、证据；在独立输出目录构建基线。禁止：覆盖现有构建、顺手修玩法、为补特效重构 Sim。

| 子模块 | 成果 | 验收标准 |
|---|---|---|
| M0.1 完成版快照与资产盘点 | 当前变更/未跟踪文件清单和hash、资源/入口映射、基线构建与截图 | 快照覆盖最新未提交代码及 .meta；能说明每行目录是保留/增强/新建/待契约 |
| M0.2 表现语义与契约设计 | 每项来源、目标、时点、可见性、停止条件；缺口及具体接口提案 | 覆盖破盾时序、地堡静默伤害、驻军射击、同卡重放、AOE 去重；现有消费者不被遗漏 |
| M0.3 取证与性能基线 | 正常玩家机位、三种背景、固定seed/命令场景、基线性能和回归索引 | 实际播放器画面有对应hash；玩家输入测试与内部调用自检分栏；现有缺陷可复现或列待验 |

审核：三份成果一次隔离计划审核。M0.2 的提案是设计证据，代码契约修改另在落地时单独审。

大模块验收：409/38 是历史锚点，复跑要绑定当前工作树和日志；有新增/删除用例则逐项解释差异。已有卡位补偿不能算自然流程通过。交付 `baseline.md`、`effect-ledger.md`、`presentation-contract.md`、`evidence-index.md`。

升级：新工作树不含完成版、GDD/当前代码冲突影响表现、构建本身不通过、目标硬件性能显著不足。先记录并隔离影响，不扩做玩法修复。

## M1｜最小公共表现基础

目标：一个真实事件能可靠地产生正确效果，并能在暂停、换边和重开时正确结束。

依赖：M0。工作量参考15%。允许：新增小型 View 表现组件、公共效果资源目录、对 `BoardView`/`GameBootstrap` 的窄接线、定向测试。涉及既有 `SimEvent`/Sim查询的改动必须先通过具体契约审批。禁止：新框架平台、替换现有整个事件总线、用效果脚本计算伤害。

| 子模块 | 成果 | 验收标准 |
|---|---|---|
| M1.1 资源注册/池/时钟 | 最小配置、按效果族池、当前对局根、战斗/UI时钟 | 热路径无new材质；×1/2/4/8与暂停正确；池超量按优先级降级 |
| M1.2 表现数据适配 | 合同落地、tick快照/事件记录、来源与攻击组ID | 同击多目标一次出招；盾血结算后判断；缺目标也不异常；旧音频/统计消费者兼容 |
| M1.3 可见性与清理 | FogRules统一适配、生命周期撤销、场景级清空 | 隐藏攻击者轨迹不泄露；三次换边/重开无残留；未知建筑不会透露新受损状态 |

审核：若 M1.2 改公共接口，M1.2 单独审核，不重复计入普通批；M1.1/M1.3在本大模块收尾做两项尾批。若均为内部实现，按1–3整批审。新订阅接口/资源公用结构同样登记兼容边界，不能只盯 Sim。

大模块验收：用一个临时内部验证效果覆盖真实事件链和清理；不能宣称这就是美术样板通过。交付接口/配置说明、生命周期图或表、开关对照日志、定向测试/播放器短片。

升级：必须改变结算时机、观察接口影响既有统计/音频、对象池跨局归属不清、同步结构无法保证事件顺序。

## M2｜三组战场风格样板

目标：在实际地面、镜头和兵团密度中锁定统一质量，随后复用。

依赖：M1。工作量参考17%。允许：下列三个样板所需资源、有限接线、展示场景和参数配置。禁止：完成所有英雄后才问风格、临时提高全局曝光制造“好看”、为展示假装发生伤害。

| 子模块 | 内容 | 验收标准 |
|---|---|---|
| M2.1 重锤打盾 | 镇岳打磐石：出招/盾承击/破盾/普通命中 | 盾变化与破盾一一对应；正常镜头识别“锤打盾”；无夸大AOE |
| M2.2 远程命中与状态 | 星落对逐风及免疫/例外对照，含一组士兵 | 紫束出射与真实命中同拍；沉默只在真生效时出现；密集射线可读 |
| M2.3 海克斯与建筑 | 铁壁重装增益、普通建筑受击/废墟、现有屏障风格并排 | 铁壁不生成地堡；塔毁后无继续攻击；浅石地上弱/中两档效果均能辨认 |

审核：1–3一次隔离审核，随后制作人看样板。每组提供同机位无新效果/新效果A/B短片（建议每段8–12秒、1倍速），附图中效果落点和状态数值。A/B只比较一个主要风格变量，不同时改颜色/大小/曝光/镜头。

大模块验收：建立“金样”资源和参数版本，制作人选定后 M3–M5沿用；尚未得到样板意见时可继续独立的契约/测试工作，不能把全部P1资源量产。旧屏障若无需改变，记录“保留”即完成复用决定。

升级：两轮样板仍不可读或未接近预期，先定位形状、尺寸、节奏、背景冲突，不继续加粒子层；需要新动画、付费包或整体渲染重做时出单独提案。

## M3｜六英雄和通用战斗完整覆盖

目标：六英雄在真实兵团战中有各自读感，基础/升级/克制/免疫正确。

依赖：M2金样、M1契约。工作量参考25%。允许：英雄族效果资源、武器表现锚点、英雄效果路由、C01–08、H01–12。现有主将/士兵模型和核心动画保持资产来源，必要动画参数适配仅限表现，必须验证与真实攻击一致。

| 子模块 | 覆盖 | 关键验收 |
|---|---|---|
| M3.1 磐石 | H01/H02，C02–04/C07 | 护盾承击/破盾/回盾/坚定免疫，士兵反例 |
| M3.2 镇岳 | H03/H04，C01/C05复用 | 对盾/普通目标、升级、阵亡；不重复制作M2样板 |
| M3.3 断峰 | H05/H06，C06迟滞 | 普攻/拒马/破军多目标，只一次主出招 |
| M3.4 逐风 | H07/H08，C08 | 普通移动/冲锋/打断/飞掠/撤退，残影不落后实际位置 |
| M3.5 坠日 | H09/H10 | 弹迹、镇岳重伤/脆弱、无效对象对照，移动靶/目标死亡 |
| M3.6 星落 | H11/H12，C06沉默 | 沉默/镇岳例外/诛灭、主将与士兵强弱、驻军出射 |

审核：1–3、4–6两批；公共接口差异仍从普通批摘出先单审。跨英雄同类问题修公共入口后，对所有消费者回归，不能六份复制修复。

大模块验收：六英雄各一段正常战斗+升级/机制证明；至少一段3v3或更密实战，测试同 tick互相致命、同时多目标、已隐藏目标、主将死亡后士兵、进出驻军。统一死亡/状态清理不能只测最后开发的英雄。

升级：金样在新武器/尺度失效、动作无法与攻击节奏对齐、机制文案与源码冲突。原攻击动画没有合适接触帧时先用短即时命中保证反馈准确，不借机改变战斗速率；动作精修另列工时。

## M4｜八海克斯与状态管理

目标：玩家能看懂当前卡、受益对象、层数/目标、替换和结束，同时保留世界可见性边界。

依赖：M1/M2，共享M3状态样式。工作量参考15%。允许：海克斯表现适配、UI已有区域内的短提示、X00–08；必要只读查询按契约审。禁止：八卡变十卡、铁壁召唤堡垒、篡改有效期、额外扣费、把曲径通幽做成隐身。

| 子模块 | 覆盖 | 关键验收 |
|---|---|---|
| M4.1 激活/覆盖共同骨架 | X00和八卡通用生命周期 | 释放成功才播；同卡再次激活可识别；双阵营并发、失败和取消 |
| M4.2 进攻与机动卡 | X01钢铁/X03陷阵/X04轻装 | 资格变化、短免伤结束、逐层到期、控区出入 |
| M4.3 防守卡 | X05铁壁/X06以逸/X08沙包 | 重装军团资格、非重装反例、单目标死亡、边界撤销 |
| M4.4 运营与通行卡 | X02快速/X07曲径 | 生产与名额提示、塔豁免实际状态；不泄露隐藏路径 |

审核：1–3一批，4为大模块尾批；若1改公共契约则先单独审，普通2–4仍为三项一批。不重复审已放行部分。

大模块验收：八卡逐项触发，A→B覆盖、同卡刷新、到期、目标消失、双方分别使用、同画面双方同时使用；至少一例常规对局窗口内真实UI抽选释放，其余可训练场定向复现。程序化定向抽卡只作规则覆盖，不把它计为用户随机体验测试。

升级：无法权威读取目标/层数/阶段、GDD描述和程序资格不同、拟新增全图暴露单位信息。必须把“全图激活提示”与“可见单位附着效果”明确拆开。

## M5｜建筑、道具、操作与对局反馈

目标：攻城和道具真正生效时看得见，失败时不误报，进入/退出一局表现完整。

依赖：M2，集成M3/M4。工作量参考10%。允许：B01–08、T01–06、U01–07的表现和现有声音对齐；保留已拍板屏障形状、烟雾阈值、选中规则和UI布局。

| 子模块 | 范围 | 关键验收 |
|---|---|---|
| M5.1 建筑/屏障 | B01–08 | 塔/驻军射击来源、普通受损与废墟、占领/重建、屏障多点受击/破段 |
| M5.2 两道具 | T01–06 | 世界/小地图攻城锥、阵地合法/非法/取消、成功部署/脉冲/到期/被毁 |
| M5.3 操作和对局收束 | U01–07、已有音效对齐 | 出生/补兵/升级、EP、加时/结算、暂停/倍速、练习场换边/重开 |

审核：1–3一批，公共契约修改单审。与M2重叠的已通过效果只核集成和回归，不重造资源。

大模块验收：从玩家下令起自然行军到攻击/占领/毁坏/重建；新地堡从选择→放置→攻击→移除；失败不扣错资源、不播成功；“旧自检自动解卡”的场景明确标注，另补无补偿录制。可见音画配对、全局音效并发不因新增 VFX 重复调用。

升级：需要增加道具飞行时间/冷却/范围、占领保护等规则；发现已有卡位、幽灵拦截或错误武器问题时单独报告，不能用光效盖住。

## M6｜性能、回归与最终交付

目标：在完成版中可用、可维护、可回退，并且制作人能直接看一份短证据包裁决。

依赖：M3–M5。工作量参考10%。允许：VFX预算/LOD/精简档、资源压缩和Shader保留、回归/取证、文档。禁止：删玩法、减单位数量、改镜头/全局曝光偷偷换取性能。

| 子模块 | 成果 | 验收标准 |
|---|---|---|
| M6.1 密集战斗与质量档 | 固定seed/命令、VFX开关三次对照、普通/精简档 | 预算达标或提交真实差额与裁决；高倍速无无限排队；关键反馈不被士兵粒子淹没 |
| M6.2 全矩阵和构建回归 | 规则/生命周期/玩家输入/实际播放器视觉记录 | 409历史基线无未解释丢项；38判据可对账；新增VFX断言逐ID可查；无补偿操作覆盖单独存在 |
| M6.3 制作人交付包 | 最终播放器、6段精选证据、完整索引、参数手册/回滚表 | 制作人能启动看效果；新文件和材质被打包；所有目录条目状态已结案或明确获准延期 |

审核：1–3一次隔离终审，再由总编排核全局目标和制作人终审。程序化硬事实决定正确性，制作人决定审美；不以画质参数或粒子数量自动判美术通过。

交付精选六段建议：重锤破盾、远程状态/免疫、骑兵冲锋打断、双阵营海克斯替换、占领/拆毁/道具、密集战斗/倍速/暂停。每段10–20秒即可，完整边界测试留索引不塞进汇报。

## 通用预算、升级与收口

不设置臆造的精确 token 预算。执行编排只拿当前模块卡+相关源码/符号+未关闭缺陷，不复制整个项目历史；机械清单/hash/计数由脚本完成。资源先复用、样板先对比、验证只覆盖真实风险。

普通代码审核同批连续三轮未收口，交制作人指定的更高一级裁决者：重新审原疑点与修复史，有证据才可放行。审查员本人不得审核自己提交的代码。同一视觉样板最多两轮无方向迭代，之后先定位原因再继续。未批准的按量生成/资产购买本包预算为0；确需外部资源先提供用途、数量、费用上限和替代品供制作人裁决。

每个子模块完成时同步：`PROJECT_STATE.md` 当前项、效果台账、任务/产物hash、测试/证据、待验、未提交状态；失败也登记。大模块完成再更新 `PROJECT_BRIEF.md` 和总体索引。是否提交/合并按实施时制作人的仓库授权处理，本规划不替用户提交整片现有脏工作树。
