## 3. 交付目标

在正常俯视镜头下，玩家能快速看懂：谁在攻击谁、攻击是否命中/被盾承受、六英雄的不同作用、关键状态是否生效、海克斯换成了什么、建筑是否被占/拆/重建、道具是否成功。

完成定义：特效目录每行有唯一负责人、权威触发源、取消/结束规则、资源和接线位置、证据以及验收结论。不能以“有粒子”“截图漂亮”或“测试全绿”代替实际交付。

P0 = 信息正确与可读性，所有 P0 必须交付。P1 = 在 P0 上增加质感，也属于完整版本范围；若要省略必须记录制作人缩减范围，不能静默降级。P2 = 可选扩展，不阻塞本轮：屏幕震动、全屏色差/扭曲、专门死亡动画、电影镜头、购买资产和新 3D/动作生成。

音频纳入**已有事件和特效对齐、节流、避免重复播放**，不重做 BGM、不开展完整声音制作。没有音源的可选装饰效果不阻塞 P0。

## 4. 美术方向与可读性规范

风格：与已确认的卡通盔甲、武器和地堡一致，使用清楚的形状、短促的节奏、小范围的亮部。保留钢铁/尘土/护盾/魔法四种材质感；不能让全部技能都变成不同颜色的圆环。

- 信息层级：指令目标与危险边界 → 英雄关键状态/破盾/冲锋 → 英雄普攻 → 士兵普攻 → 环境装饰。预算紧张时由后往前降级。
- 阵营只承担敌我识别，沿用蓝/红；选中态沿用绿色细脚环。技能主题色用于内核、轨迹或图标，不能把红黄色坠日攻击误读成必为敌方。
- 六英雄主题：磐石=钢银盾面裂纹；镇岳=钢锤钝击与土金碎屑；断峰=窄银刃与琥珀短弧；逐风=方向性风带/蹄尘；坠日=既定红黄箭状射线；星落=既定紫色魔法束与封口符号。沿用已拍板红黄/紫色，不擅改为火焰持续伤害。
- 常驻状态以头顶/侧面小标记为主；脚下不叠大面积光圈。一个英雄默认最多同时显示两枚关键状态图标，其余用“+N”与选中详情承接；优先顺序需 M0 确认并登记。
- 瞬时表现起始建议：命中亮点 0.04–0.08 秒，主体 0.08–0.18 秒，收尾 0.10–0.30 秒；按英雄重量调整。这里是调参起点，不是已通过观感测试的硬数值。
- 普攻不强制全屏闪白、镜头震动或真实停帧；不改变仿真时间。可选“降低闪烁”档压缩亮度变化，仍保留命中和状态形状。
- 射程、扇形、放置范围只有真实规则对应时才能画成明确边界。装饰冲击环不得伪装成伤害半径；地堡脉冲以当前 2 米查询口径核对。
- 在浅石地/草地/阴影分别验收；泛光关闭仍应看懂主体。禁止通过整体加 Bloom 掩盖贴图和形状质量。

## 5. 推荐架构和前置契约

推荐形成一个轻量的表现协调层：权威事件/只读状态 → 每 tick 的表现记录 → 可见性过滤与预算 → 池化效果 → 生命周期清理。名称和最终类拆分由执行编排决定，不先搭通用特效编辑器。

优先复用 ParticleSystem、网格/轨迹、项目内 URP 材质、UI Toolkit。当前效果规模先不增加 VFX Graph、Addressables 或收费插件。纹理/曲线/配色资源与事件接线分离，共享材质通过受控实例参数变化；命中时不新建材质。

必须处理的七项语义：

1. **结算阶段**：`QueueDamage` 在盾血扣减前发送 `DamageDealt`，护盾按受害者本 tick 总伤害聚合吸收。命中可由事件触发；破盾/死亡必须取结算后快照或明确结算后事件。禁止逐个事件在 View 重算伤害，禁止把每条 Amount 当成实际掉血。
2. **来源身份**：`AttackerId=0` 是无明确来源，不自动等于攻城锥；屏障路径另有一条攻击者对自身的 `DamageDealt`，不能生成自伤闪白/自射弹道；地堡脉冲当前直接扣血，不统一发命中事件；驻军射手的攻击者 ID 指主将，但弹道出发点应在实际驻扎建筑射击口。
3. **攻击一次与伤害多次**：溅射/扇形一击可能发多条伤害；只播一次出招，受害者各播命中。不能简单用“同 tick 同攻击者”永远去重；若存在同 tick 多次合法攻击，需要权威攻击序号。
4. **表现时间**：对局倍速在 `GameBootstrap.Speed`，不靠假定 `Time.timeScale`。状态和范围跟 Sim tick；战斗粒子/轨迹跟对局时间并在暂停时冻结；菜单和暂停 UI 动效使用独立 UI 时钟。×8 时合并低优先级命中，不能累积成烟花。
5. **消失与替换**：死亡/移除会立即拆 EntityView；需要余留的命中/死亡效果应在移除前获取允许展示的位置快照，挂到当前对局效果根；新对局/换边/退出清理池、句柄、订阅、节流时钟，不能带入下一局。
6. **视野**：己方/敌方单位、未知/过期情报建筑按当前 FogRules，不能用 Renderer.enabled 或镜头内外代替规则。不得从迷雾中追踪隐藏单位到最新位置；轨迹也不能暴露隐藏发射源。GDD 的“海克斯激活全图可见”按双方可见的卡名/阵营提示处理，单位附着效果仍受视野约束。
7. **真实状态**：动画 `state=Attacking` 是持续状态，不是一击的事件；海克斯激活不等于每个单位都享受每项加成；拒绝/取消操作不播成功效果。复杂状态通过权威查询，不能在 View 复制一套数值规则。

M0 要先提交《表现契约表》：每种效果记录现有来源、时点、目标/命中点/来源位置、有效性、缺字段、兼容策略。已有字段足够则直接使用；仅公开查询缺口则增加窄的只读快照；瞬时来源缺口才考虑追加观察事件。

**本规划不授权改战斗数值、结算顺序或公共签名。** 必要的公共接口由执行编排提出具体签名、字段语义、发出时点、现有消费者影响和反向测试，送制作人指定的总编排/契约裁决者书面确认后单独审核。非相关模块可继续，不因一个契约卡住全项目。

## 7. 技术预算（待 M0 测量后冻结）

以下是本计划提出的初始预算，不能写成当前项目实测值：

| 项目 | 建议目标 | 测量/调整规则 |
|---|---|---|
| 基准画质 | Windows，1080p，正常对局 ×1，目标 60 FPS | 指定硬件、镜头、战斗密度和构建模式；先测原 Demo |
| VFX 增量帧耗 | VFX 自身 CPU p95 ≤1 ms，GPU 增量 p95 ≤2 ms | 同一回放种子/输入，开关 VFX 各三次，预热后取 60 秒；不能以两份整帧 p95 相减冒充精确 GPU 成本 |
| 稳态分配 | 新 VFX 更新/发射热路径 0 B/frame 托管分配 | 预热后用 Profiler 定位；全游戏已有 GC 另行归因 |
| 同时活动一次性实例 | 初始全局上限 192，其中至少 32 预留关键反馈 | 超量合并士兵命中；破盾/死亡等可退化为轻量符号，不能静默漏掉 |
| 可见粒子 | 普通档初始总预算 3000，精简档 1200 | 这是全系统共享预算，不能每个效果各领一份；状态标记另设上限 |
| 主体复杂度 | 常规命中 1–2 渲染层，关键破碎 3–4 层 | 只作起点，按 overdraw 和真实观感调 |
| 新增贴图 | 通用图集 512/1024 起步；新增运行时纹理预算 32 MB | 以目标格式、mipmap 和真实驻留计量；不默认铺满 2K/4K |
| 稳定性 | 三次换边/重开无旧效果，压力运行后活跃量回落 | 池容量允许保留已预热数量，不能单凭“内存没归零”判泄漏 |

正常模式实体压力按当前名额上限加士兵/补兵峰值测量；训练场名额无上限，至少构造 300、600 个可见单位作为压力样例，并明确这不是无限负载性能承诺。×8 必测事件洪峰和反馈不滞后，帧率单独记录。若原 Demo 已达不到目标，拆分原有成本和 VFX 增量，不能为了特效偷偷减少单位、视野或 AI 计算。

## 9. 外部技术依据

Unity 官方 URP 粒子材质文档描述了 Transparent 和混合模式；本计划据此要求在目标播放器验证 alpha 淡出，不只修改颜色透明度：[Particles Unlit](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/particles-unlit-shader.html)。粒子系统有独立模拟速率设置，项目仍须显式适配自己的倍速/暂停：[simulationSpeed](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/ParticleSystem.MainModule-simulationSpeed.html)。性能取证使用 Unity Profiler：[Profiler](https://docs.unity3d.com/6000.0/Documentation/Manual/profiler-introduction.html)。预算数字均为本项目规划建议，不来自这些文档。
