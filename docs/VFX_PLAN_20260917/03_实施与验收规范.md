# 实施与验收规范

本文件规范执行步骤；命令示例与拟新增工具不得被写成“已经执行”。当前游戏代码和资源未在本轮变动。

## 1. 开工与基线保护

1. 阅读本包、`PROJECT_STATE.md` 最新尾部、`PROJECT_BRIEF.md`，确认制作人当前指令与目标工作目录。
2. 记录 HEAD、tracked diff、未跟踪文件及 .meta；将需要复现的完整源码/配置/资源做可恢复快照并hash。排除 Library/Temp/凭据。仅记录HEAD或只复制tracked文件都不合格。
3. 不直接复用旧发布目录。选择新的 `IC_BUILD_DIR`，并确认其绝对路径属于本任务输出目录；先产出基线版本。
4. Unity GUI/MCP 与 batchmode 不并发操作同一项目。优先已有播放器取证；需编译时先正常结束占用实例，遇未保存编辑不要强杀。编辑器重启后确认场景、项目路径、Play状态；9月9日的PID/连接记录不能当今天仍连通的证据。
5. 先确认图像和输入通道。MCP能查询/进入Play不等于能验证真实鼠标；能够发内部命令不等于能证明UI没吞点击。不可控时如实记玩家输入待验，不重复空启动。
6. 用固定随机种子、真实命令序列、固定相机/分辨率/光照做基线。调试场景可摆位测试单项数值；集成场景必须由真实入口自然推进，不能把对象直接摆到终态。

## 2. 每个效果的标准制作步骤

1. **定义**：领取效果ID，写清玩家应看懂什么、为何触发、落点/方向、何时停止、谁能看见、优先级和复用关系。
2. **验证语义**：在未新增特效前记录权威事件/状态前后值。缺事件先走契约，不通过监听音频/动画名称猜成功。
3. **灰盒**：用现有基础纹理/网格做最少渲染层，先证接线/可见性/清理。灰盒只过工程门禁，不标美术通过。
4. **资源制作**：依M2金样调整轮廓、节奏、渐变、贴图；普通冲击与常驻状态分开。每个效果至少有可编辑源文件、运行时资源、参数说明、许可证或自制来源。
5. **接线**：从批准的数据适配层消费事件/状态。效果资源不保存实体可变引用跨局；句柄绑定对局代号和来源实例，避免ID在重开后复用。
6. **小范围验证**：成功一次、失败/取消一次、结束一次；再测主将/士兵、两阵营、不同背景、暂停和倍速。
7. **机器门禁**：编译、定向逻辑/生命周期验证、资源缺失扫描、diff检查；接口/核心接线需相关旧测试。仅改贴图/色曲线不编造大量镜像测试。
8. **取证**：同机位前后片段，至少含命中前/主读点/结束三时刻；建立事件行→帧时间→效果ID对应关系。
9. **批审/修复**：达到三个普通子模块后脚本封包；疑点返源码/资源原提交者，修复后只复审疑点与受影响回归；公共接口单独审。
10. **记账**：登记版本/hash/产物路径/测试/视觉结论/已知限制，更新 PROJECT_STATE；进入下个子模块。

## 3. 资源与技术美术规格

推荐新增目录（M0 先确认不与既有目录冲突）：

```text
Assets/Resources/VFX/
  Common/  Heroes/  Hex/  Buildings/  Tools/  UI/
  Materials/  Textures/  Config/
Assets/Scripts/View/VFX/
docs/VFX_EVIDENCE/<模块ID>/
```

既有 `WallFx`/`BeamFx` 等保持原路径，替换时指定唯一消费方；先不为整理目录移动所有旧资产。大视频和Profiler二进制可置独立交付目录，由索引绑定hash。

命名：`FX_<领域>_<行为>_<变体>`；文档效果ID与资源名称建立表格映射。不要把每种颜色复制成完全独立源码。

资源参数至少包含：效果族、版本、持续时间、发射节奏、最大实例/粒子、坐标空间、锚点及fallback、材质/纹理、普通/精简档、暂停/倍速策略、视野策略、结束条件。局部和世界空间须明确；武器附着跟随源，落点冲击不跟随逃跑目标。

材质检查：URP兼容、正确Transparent混合、顶点色alpha能影响最终像素、ZWrite/遮挡正确、白石地不消失、夜暗处不爆白、构建Shader不被剔除。加色只作为短核，不承担所有主体轮廓；碰到加色不读alpha应修混合或颜色表达，不提高发光强度掩盖。

对象池检查：预热容量、借还配对、重置颜色/缩放/粒子时间/目标引用、播完/被打断/目标消失/换边/退出都能归还。可见性丢失时停止相应附着效果；重新可见时重建当前持续状态，不补播视野外已错过的攻击历史。

不默认开启粒子物理碰撞、投影、实时点光源和大面积屏幕扭曲。需要时由执行编排用实测收益/成本决定；真正能影响寻路、伤害或选中的Collider不得加到表现资源上。

不使用特效随机数消耗 `Sim.Rng`。复现需要的噪声种子使用局部表现随机源，从已记录的事件序号派生。录制重放时随机效果可复现；线上仿真状态不得因画质档变化。

时间对齐：×1时英雄命中主读点与权威结算差建议不超过50ms（60FPS约3帧，执行前冻结口径）。当前事件不含出手预告，不能先生成长飞行再任由血条提前下降；优先即时快束或补只读出手契约。倍速状态有效期严格跟tick，一次性装饰可设最短可见窗但不能跨阶段保留有语义的状态图标；常规“暂停”冻结战斗视觉，不仅停Sim。

视野细则：

- 目标不可见：不附加当前状态，不弹出新伤害数字，不展示隐藏死亡位置。
- 来源不可见、目标可见：只允许目标侧命中或按已批准规则裁剪的末段，不画一条完整箭线指向隐藏来源。
- 中段越过迷雾：按当前可见区域裁剪；不能只检查起终点后全线放行。
- 建筑模型可见不代表其实时血量/驻軍可见。新烟雾/伤害/占领特效按情报可见性处理。
- 海克斯公告是明确的全局信息例外，携带卡名与阵营，不携带沙包目标坐标、受益军队位置。

## 4. 验收矩阵

每行须对应真实证据，不要求所有效果做无意义笛卡尔积。高风险共用路径全测一次，各效果补本身正例和主要反例。

| V01 | 真实命中、同一击多个受害者、同tick多击 | 一次出招，真实受害者各有反馈；没有凭伤害条数重复出招 |
| V02 | 有盾、恰好破盾、溢出伤害、回盾后再破 | 破盾次数与结算后的盾状态转变一致；无View重算伤害 |

| V05 | 冲锋发起/成功首击/拒马/沉默/取消 | 风带方向和状态正确，结束当帧或下一渲染帧清理 |

光学验收：至少1600×900现有窗口和1920×1080；正常/最远镜头；蓝红互换。高分辨率支持范围由M0实测确定。精选片必须是实际游戏视角，近景只用来排错。

视觉模型提问采用“描述画面中发生了什么、哪里看不清、哪些信息互相冲突”，不要把预期答案塞进去。像素占比、粒子计数证明不了命中语义；事件日志也证明不了画面好看，必须双证据。

现有自然行军卡位观察项单列：未补偿自然流程卡住时，记录为现有玩法问题并挂对应效果“被该路径阻断”；不能让测试传送结束后把整条真实命令路径标绿。

## 5. 可执行入口与命令要求

开工只读：

```powershell
git -C D:/DevTools/IronCurtain status --short
git -C D:/DevTools/IronCurtain rev-parse HEAD
git -C D:/DevTools/IronCurtain diff --check
```

已有构建入口：`IronCurtain.EditorTools.BuildPlayer.Perform`（`Assets/Editor/BuildPlayer.cs`）。现有默认输出 `D:/DevTools/build_ic` 是用户Demo，**每次本任务构建必须覆盖 IC_BUILD_DIR 指向独立目录**，不得覆盖默认交付。以下只是执行模板，执行前核对Unity路径与工作树：

```powershell
$env:IC_BUILD_DIR = 'D:/DevTools/build_ic_vfx/M0_baseline'
& 'D:/Unity/Editor/Unity.exe' -batchmode -projectPath 'D:/DevTools/IronCurtain' -executeMethod IronCurtain.EditorTools.BuildPlayer.Perform -logFile 'D:/DevTools/build_ic_vfx/M0_build.log' -quit
Remove-Item Env:IC_BUILD_DIR
```

模板输出父目录由执行者先创建；构建失败也应在 finally 中恢复/清除本轮环境变量，如原来有值则恢复原值。不要默认以一次进程退出码判断构建成功：读取BuildReport、日志、输出exe存在性及其时间/hash。

已有 EditMode 入口：

```powershell
& 'D:/Unity/Editor/Unity.exe' -batchmode -projectPath 'D:/DevTools/IronCurtain' -runTests -testPlatform EditMode -testResults '<本批独立目录>/editmode.xml' -logFile '<本批独立目录>/editmode.log'
```

占位路径由执行编排生成并实际存在后使用；不要与GUI并开同一项目。核对编译完成时间、程序集新鲜度、测试数/失败数/跳过数，不能只用exit0；不为了凑409掩盖新增失败。纯素材修改做资源/播放器验证即可；修改共享接线或Sim观察接口时补受影响回归，集成时全量跑一次。

已有播放器自检：`IC_ACCEPT=all`，入口 `Assets/Scripts/View/IcAcceptance.cs`。它含程序化和反射调用，单独提供自动规则/接线证据；真正鼠标输入另录V17。该工具的`hexfx`等名字并不证明完成本包要求的动态特效。执行时先查其证据输出目录，避免覆盖桌面已有作品集证据；若路径写死，则用独立测试工具/可配置输出扩展后单独审，不直接原地覆盖。

拟新增而当前**不存在**：VFX专用场景驱动、效果事件记录器、性能采样/目录覆盖检查。由M0/M1细化实现和入口，不能在报告中引用未创建的命令。新自动用例不得修改正式对局规则来造出效果。

Profiler取证绑定构建模式；最终美术使用正常播放器复核，不拿Editor场景窗口或离屏Camera.Render当含UI的最终画面。录制缺帧、曝光自动变化、镜头没对准时重录该段，不重做全部测试。

## 6. 脚本化审核包

每批只含本批任务卡、涉及的当前源码/资源清单、必要接口/约束、差异和独立证据；不要把执行者“应该通过”的倾向带给审核员。

必填字段：batch_id、module_ids、round、submitter、baseline_head、working_snapshot_hash、task_hash、candidate_manifest_hash、changed_paths、tests、visual_evidence、known_issues。hash记录放包外manifest，避免文件把自身hash写进自身造成循环。

批次例：M3-B1={M3.1,M3.2,M3.3}、M3-B2={M3.4,M3.5,M3.6}。M4四子模块默认先1–3再尾批4。单独审核的公共接口子模块从普通批队列中取出，不重复累计；接口消费者集成回归仍保留。

审核结果：每项编号、文件/资源、可复现事实、影响、严重度、是否阻断、原提交者。拦截→返原提交者→修复或证据反驳→重审受影响部分。同批连续三轮未收口才升级；升级不是自动放行。

## 7. 证据与状态模板

每个效果台账行至少为：

```text
效果ID / 所属模块 / P0或P1 / 保留或新增
触发来源 / 结束规则 / 可见性 / 倍速暂停行为

正例 / 反例 / 生命周期 / 视频时间码 / 日志事件行
机器检查 / 独立审核批次 / 已知限制
工程验收 / 程序化运行验收 / 真实输入验收 / 制作人验收
原提交者 / 当前负责人 / 下一步
```

沿用工作流三态：工程验收、实机验收、制作人验收；为防自检混淆，实机证据内部再区分程序化运行和真实输入。只适用事件播放的素材项可把真实输入记为“由集成V17覆盖”，不为每个贴图重复点一次鼠标。

单个模块交付包：`task.md`、`manifest.json`、`acceptance.md`、`test-results/`、`clips/`、`perf/`、`rollback.md`。文件名是约定，脚本可按现有管线调整但必须保持可定位。失败也留证据。

## 8. 回退与交付检查

- 配置切换可禁用新增表现，不能关闭所有反馈后仍叫“完整成品”。新效果回退到原有版本时，老资源与路由保留至验收通过。
- 每大模块保存具体文件差异/新增资源名单和对应原文件hash。回退只针对本模块，不用整库reset破坏用户已完成Demo。
- 卸载/切换新表现后，规则、旧音效和输入链仍可运行；事件订阅和池销毁对称。
- 交付播放器含Shader、字体/图标和材质引用；冷启动无粉色/丢贴图，三次重开无跨局特效。
- 最后同步 `PROJECT_STATE.md` 和 `PROJECT_BRIEF.md`，说明实现范围、通过项、延期项、证据、构建路径、是否提交。审美未获制作人确认时明确写“制作人待验”，不升级为已发布。

## 给下一位高级模型的启动任务

你担任《铁幕：前线》特效执行编排。请先读本目录 README、01–03，以及 PROJECT_STATE 最新尾部，按当前未提交工作树建立完成版基线；首先执行 M0，产出效果盘点、表现契约和取证/性能基线，再依 M1→M2 金样→M3/M4/M5→M6 推进。按普通每三子模块隔离审核、公共契约修改单独审、疑点返原提交者处理；不得恢复备份中与制作人最新指派冲突的模型路由。不得改玩法来配合特效，不得用旧测试结果或自检解卡补偿代替新证据。每安全小块更新 PROJECT_STATE；需要制作人裁决时提交具体对比/接口方案和影响，不只说“请确认”。
