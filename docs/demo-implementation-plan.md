## 一、目标与完成度定义

**定位**:产品级与 demo 之间 —— 打磨手感与美术后可直接发布。
**核心验证**:单线切片验证「核心战斗与克制闭环」(GDD 原话),但同时把生产/资源/驻军/攻城/EP/海克斯/AI 全部闭环,不做任何"最小可玩"的裁剪。

### 成品级验收总纲(Definition of Done)
1. **规则零偏差**:全部数值与规则 100% 对齐 GDD 表格,可逐行对表核验。
2. **机器可裁决**:≥52 条自动化断言(对齐你简历口径),含 GDD 7.1.1 五条伤害演算的精确复现;全绿才算模块完成。
3. **无死物**:任何单位/建筑/状态有输入必有反馈 —— 攻击有前摇弹道、受击有反馈、死亡有表现,绝无"面对面发呆"。
4. **手感**:攻击节奏、冲锋冲击力、拆塔爽感、占领反馈、胜利演出,由人终审。
5. **美术**:低模科幻废土 + 霓虹统一风格,UI 无重叠错位,可读性过关。
6. **稳定**:完整一局(含加时积分)无崩溃/卡死/逻辑错误;AI 能正常打完。
7. **可演示**:Windows 打包可玩 + 可直接录屏上 B 站。

## 五、提示词生成规则(计划敲定后逐模块产出)

每个模块的提示词固定六段:
1. **角色与任务**(GLM-5.3 是 Unity 资深主程,本模块只做 X)
2. **GDD 原文摘录**(只给本模块相关章节,含表格)
3. **接口契约**(命名空间/类名/方法签名/文件路径,由我先行定义)
4. **现状**(相关已有文件全文,保持连续性)
5. **硬性验收**(编译通过 + 断言清单逐条 + 明确禁止项:如 Sim 层禁 UnityEngine、单文件≤300 行)
6. **输出格式**(只输出完整代码文件,无解释)

执行循环:提示词 → GLM-5.3 生成 → **静态门禁** → **重写检测(修改类任务)** → 落盘 → Unity 编译 → read_console → 有错回喂(≤3 轮)→ 无头断言 → 截图 → flash 验收 → 全绿交付你审。

### 修改类任务特别协议(事故复盘后强制,2026-09-04)
针对"改既有文件"的提示词,在原六段基础上追加四条铁律:
1. **第 4 段必须逐字内联目标文件全文**——只写摘要的修改任务一律不发;
2. **优先补丁式输出**:要求 unified-diff 格式(锚定真实行),禁止"输出全文重构";补丁落地后跑 `rewrite_detector.py` 校验改动范围;
3. **"看不见就要求"条款**:明确写入"若提示词未包含文件源码,禁止凭空重写,只允许回复'请提供 X 文件源码'";
4. **优雅方案采用协议**:GLM 输出中与主方案不冲突的优雅设计(命名常量/显式状态/数据表等),由编排者核实无误后**采纳移植**,衡量标准=最终项目效果,成本几乎不设限(单次烧掉数十万 token 除外)。

### 授权原则(用户拍板 2026-09-04)
- GLM 表现持续靠谱且超额完成时,编排者可**适当放权**(更大绿场范围、更少拆分);与预期有出入时先**核查它实际做了什么**再定性。

### API 契约与测试模板铁律(API 调错复盘后强制,2026-09-04)
