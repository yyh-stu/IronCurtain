# M3.1 建筑占领核心 —— 意图/交换/封城/自动驻军(GL M 绿场实现+测试)

## 一、角色与任务
你是《铁幕:前线》Unity 6 项目攻城系统主程。本模块实现**建筑占领核心**:攻城意图(存建筑、后写覆盖、封城锁)、入城交换(1:1/镇岳1:2)、封城、中立直接占领、占领后自动正式驻军。只新增两个文件:`Assets/Scripts/Sim/SiegeSystem.cs` 与 `Assets/Tests/EditMode/SiegeTests.cs`。**禁止修改任何既有文件**(52 个既有测试必须保持全绿)。

## 二、GDD 规则(权威)
- 2.5.1:所有英雄均可进城交换,除镇岳交换比 1:2 外其余均为 1:1,优先消耗敌方守军;城内守军清零后建筑归属进攻方。入城交换仅依据交换比例,克制、护盾、免伤等机制均失效。据点进入交换状态立即封城,被攻击方不可进入,直到进攻方被肃清;期间进攻方可持续派兵进入。
- 2.6:中立建筑无血量、无初始归属;无人派驻时己方英雄进入直接占领;有敌方驻军需先清守军再入城;驻军清空后自动变回空置,重新占领无需消耗 EP。
- 2.4:正式驻军单建筑最多容纳 9 名兵团,不占线单位身位。
- 用户拍板(D21-D23,优先):攻城意图存建筑(SiegeIntent,后写覆盖);封城期间意图锁死不可切换,只可增援进城;交换结束解锁;占领成功幸存部队自动正式驻军(≤9,超出者离城原地待命);目标完成后部队原地待命。

## 四、接口契约(严格实现)

### SiegeSystem.cs(`namespace IronCurtain.Sim`,静态类)
```csharp
public static bool SetIntent(SimCore sim, int buildingId, Side issuer, SiegeIntent intent, out string error);
// 校验顺序:建筑存在且 Kind==Building → 否则 error="目标不是建筑"
// intent==None → 清空 Intent/IntentIssuer(允许,封城中也允许?不:封城中一律拒绝,见下)
// building.Sealed → error="封城中不可切换意图"
// building.Side==Neutral 且 intent==Destroy → error="中立建筑不可摧毁"
// building.Building==Base 且 intent==Capture → error="大本营不可占领"
// 通过 → 写 Intent=intent, IntentIssuer=issuer
public static SiegeIntent GetIntent(SimCore sim, int buildingId); // 建筑不存在返回 None
public static bool IssueOrder(SimCore sim, IReadOnlyList<int> unitIds, int buildingId, out string error);
// 建筑校验同上;对每个 unitId:实体存在且 Kind==Unit 且未死 → 设 TargetBuildingId=buildingId,
//   并 SetMoveTarget 到"建筑前方一格"(进攻方向:建筑 Col±1,取与单位同侧最近格;行序 1/0/2 找空,被占则退而求其次相邻格,仍被占则跳过该单位)
public static void Tick(SimCore sim, float dt);
// 每 tick 执行(按此顺序):
// 1) 到达判定:单位 TargetBuildingId!=0 且 !HasMoveTarget(已到建筑邻格)→ 读建筑 Intent:
//    - Capture 且建筑守军>0 → 单位入城交换:从格位移除(释放占用)、加入攻方"城内交换列表"、
//      State=Exchanging、建筑 Sealed=true
//    - Capture 且守军==0 → 直接占领(见 2);中立建筑占领时补配置血量(MaxHp/Hp=BuildingConfigOf)
//    - Destroy → 本模块只留钩子:State=Attacking(拆塔结算在 M3.4)
// 2) 占领执行(直接占领或交换胜利):建筑 Side 翻转为攻方阵营;若原中立则按配置补血;幸存攻方单位
//    自动正式驻军:依次加入 GarrisonFormal 至 9 人为止,超出者离城 Idle 原地待命;所有参与者清 TargetBuildingId
// 3) 交换结算:对每座 Sealed 建筑,每 10 tick 结算一轮:1 名攻方城内单位 与 1 名守方 GarrisonFormal[0] 互换
//    (攻方为镇岳则守方-2);优先消耗守军;守军清零 → 建筑归属攻方(走 2);攻方清零 → Sealed=false,
//    意图保留,剩余守军留城
// 4) 驻军单位不参与移动/战斗(MoveUnits/CombatUpdate 会跳过 GarrisonBuildingId!=0 的单位——由编排者保证,
//    本模块只需正确维护 GarrisonBuildingId 与 GarrisonFormal/GarrisonTemp 列表)
```
城内交换列表实现:用 `static Dictionary<int,List<int>>`(建筑id→攻方城内单位id)存于 SiegeSystem 内部,或建筑实体加字段均可——**不得改 Entity**。推荐前者,注意清理(建筑易主/交换结束时清空对应键)。

### SiegeTests.cs(EditMode,[Test] 10 个)
场景常量:蓝塔 (1,6),红塔 (1,22),中立资源点 (1,14);中立建筑 `sim.SpawnBuilding(Side.Neutral, BuildingId.ResourcePoint, pos)`。
1. 中立无人占领:蓝 1 单位 IssueOrder 中立点 → 到达后建筑 Side==Blue,且补上配置血量(Hp>0);单位自动驻军(GarrisonFormal 含其 id)
2. 意图后写覆盖:SetIntent(红塔, Blue, Capture) 后 SetIntent(红塔, Blue, Destroy) → GetIntent==Destroy;IntentIssuer==Blue
3. 封城锁意图:红塔有红方驻军 1;蓝方 2 单位 Capture 进城(Sealed==true)→ SetIntent(…,Destroy) 返回 false 且 error 含"封城"
4. 交换 1:1:红塔守军 2,蓝 2 单位攻城 → 守军清零、攻方幸存 0(1:1 互换)→ 建筑归属 Blue,Sealed==false
5. 交换 1:1 且攻方多余:守 2 攻 4 → 攻方幸存 2 自动正式驻军(GarrisonFormal.Count==2),建筑归 Blue
6. 镇岳 1:2:守 2 攻 1(镇岳)→ 守军清零,镇岳存活,建筑归 Blue
7. 攻方被肃清:守 3 攻 1 → 攻方清零,建筑仍 Red,Sealed==false,Intent 保留(Capture)
8. 增援进城:守 3,先派 1 攻(入城交换后攻方清零),封城期间再派 2 攻 IssueOrder → 进城继续交换 → 最终守军清零建筑归 Blue
9. 中立建筑 Destroy 拒绝:SetIntent(中立点, Blue, Destroy) 返回 false 且 error 含"中立"
10. 大本营 Capture 拒绝:SetIntent(敌方大本营, Blue, Capture) 返回 false 且 error 含"大本营"
