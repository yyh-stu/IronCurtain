# DeepSeek 挑刺上岗盲测包(M8.7 真实案例,已知 5 处缺陷)

> 用法:在 ZCode 开一个 deepseek 会话,把「任务单」整段粘贴过去,让它读两个材料文件后输出审查报告。
> 盲测规则:不要告诉它"这里面埋了已知缺陷"。评卷人(GLM 主编排/用户)按「评分标准」核对命中数。

## 任务单(直接粘贴给 deepseek)

你是独立代码评审员,审查一份"AI 生成的 Unity C# 代码交付"是否可信。你的唯一职责是挑刺——找出所有可疑之处,宁滥勿漏。

请读取以下两个文件:

1. `D:\DevTools\IronCurtain\docs\prompts\m8.7-retreat.md` —— 任务规格书(末尾附有修改基准的现状源码全文)
2. `D:\DevTools\glm-pipeline\m8.7.out.md` —— AI 的实际交付输出(按 `// FILE:` 标记分文件)

审查维度(逐一过,不要跳):

A. **幻影 API**:交付代码调用的类型/方法/属性/字段,在规格书、现状源码、或交付自身定义的其他文件中都不存在(会在 C# 编译时报错)。特别注意:配置加载方式、事件字段名、测试辅助方法、构造函数签名——逐一对照现状源码核实。
B. **规格偏差**:交付与规格书的接口契约、数值(系数/距离/阈值)、边界条件(哪些情况 return false / 抛异常)不一致之处。
C. **越权改动**:规格要求"除指定改动点外与现状逐字一致"的文件,交付是否夹带了规格没要的改动(增删行、改注释、重排)。
D. **内容污染**:交付的文件内容里混入了非 C# 代码的东西(如 markdown 摘要、说明文字被写进代码文件)。
E. **测试有效性**:测试是否真的能验证规格(会不会恒真断言、依赖不存在的设施、时序上永远到不了断言点)。
F. **逻辑漏洞**:撤退/防拉回/士兵同步等新逻辑里,规格没写但实现明显有坑的地方(如状态机卡死、字段忘复位)。

输出格式(严格遵守):

```
## 审查报告
### 高置信疑点(编译必错/明显违规)
- [文件:位置] 问题描述 | 依据(对照哪个现状定义/规格条款)| 验证方式
### 中置信疑点(很可能有问题,需核实)
- ...(同上格式)
### 低置信疑点(存疑但可能是我不了解的上下文)
- ...(同上格式)
### 总体结论
交付可信度评分(0-10)+ 一句话理由
```

硬性要求:高+中+低置信疑点合计**不得少于 8 条**;如果某维度没发现问题,明确写"维度 X:未发现";禁止只说好话——一份挑不出任何刺的审查报告视为失职。允许疑点最终被证伪,但每条必须写"验证方式",让评卷人可以核实。

## 评分标准(评卷人用,不给 deepseek 看)
