# 专家团编排协议（v4）

> 2026-09-09 生效。总编排=`gpt-5.6-sol`，执行编排=`gpt-5.6-terra`，审核员=`gpt-5.6-luna`；制作人保留需求、审美、手感和成本终审权。模型路由见 `MODEL_ROUTING.md`，当前事实见 `../PROJECT_BRIEF.md`。

核心原则：创作归专家、正确性归证据、调度与技术裁决归主编排、产品取舍归制作人。总编排对项目结果和实际效果负责；在此前提下必须避免无效 token 消耗，消除重复读取、无收益调用、重复转述和冗余表达，对用户一句能说清楚的事不用两句。模型输出是候选，不因“请求成功”自动成为可交付物。

## 1. 标准循环

```text
制作人目标/拍板
  → Sol 总编排界定大模块范围、公共契约授权与验收
  → Terra 执行编排拆成可独立验收子模块并路由执行
  → 脚本生成任务包（规格 + Git 基线 + 目标源码全文 + SHA256）
  → 路由到最低成本且已授权的执行模型
  → API / static / rewrite 门禁
  → parse_files.py 暂存（项目不变，生成 manifest.json）
  → 每满 5 个子模块或大模块收尾时，Luna 隔离分批审核
  → 阻断返原源码提交模型判断修复，只复审拦截部分
  → review_check.py 验证基线、产物哈希、轮次和零未处理阻断
  → parse_files.py --apply 原子落盘
  → 编译 + 断言 + 按风险补长线冒烟/截图
  → 分别记录工程验收、实机验收、制作人验收
```

产物截断、基线变化或审查出现架构冲突时立即停止重复调用。同一审核批次连续三轮被拦截后，按 Flash → Terra、Terra → Sol 升高一级；升级模型有权要求继续修复或留证直接放行。未到三轮也不必须消耗到三轮。

## 2. 分权红线

| 事项 | 有权者 |
|---|---|
| 需求、商业、费用、审美与手感 | 制作人 |
| 大模块范围、跨文档冲突、公共契约授权、最终技术裁决 | Sol 总编排 |
| 子模块拆解、核心状态机、公共接口实现与子模块验收 | Terra 执行编排 |
| 边界清晰的低中风险实现 | 2026-09-10 起可授权 DeepSeek V4 Flash；禁用窗内不得调用 |
| 常规交付疑点 | Luna 隔离分批审核；阻断返原源码提交模型 |
| 编译/API/测试事实 | 脚本、编译器和测试结果 |
| 视觉一致性线索 | 已配置视觉模型 + 程序化测量；制作人终审 |

DeepSeek 不承担美术生成或最终视觉放行，并在北京时间 `[12:00, 18:00)` 禁用；只有制作人后续明确解除才可改变。V4 Flash 最早 2026-09-10 才可试用，且仅接边界清晰、低中风险任务，不得处理核心状态机或公共接口。小而同质的任务可合并模块负责人/执行 Agent 岗位，但审核员必须保持独立只读。

## 3. 六段式任务单

1. **角色与任务**：只做什么。
2. **需求与规范**：制作人原始拍板、验收标准和优先级。
3. **输入**：目标路径、Git 基线、每个文件 SHA256 与源码全文。由 `build_task_packet.py` 生成，禁止手工摘要替代源码。
4. **输出格式**：仅允许的相对路径；代码输出使用 `// FILE: <path>`。
5. **硬验收**：编译、断言、长线冒烟、截图或导入检查中的适用项。
6. **禁止项**：不可触碰文件、不可改变的契约、不可调用的付费服务。

凡涉及公共接口，任务单必须显式列出获授权的签名、语义、兼容边界和允许文件；未写即视为无权修改。

示例：

```powershell
python D:\DevTools\glm-pipeline\build_task_packet.py task-spec.md `
  --file Assets/IronCurtain/Sim/Foo.cs `
  --file Assets/IronCurtain/Tests/EditMode/FooTests.cs `
  -o task-packet.md
```

## 4. 分批审核与代码产线

- 每个子模块独立跑机器门禁并记账，但不每块单独调用 Luna。
- 固定审核批次为 5 个子模块。若大模块共 9 个，完成 1–5 后第一次提审；全部完成后第二次仅提审 6–9。
- 大模块少于等于 5 个时，全部完成后提审一次；超过 10 个时依次每 5 个一批，最后不足 5 个的尾批在收尾时提审。
- 新批次不重复审已放行批次的全文，但全量编译、测试和集成门禁仍覆盖整个大模块。
- Luna 阻断后，脚本将报告返回原源码提交模型。该模型负责判断、修复或用证据驳回；复审包只含阻断项、修复差异及必要影响回归。
- 同批连续三轮阻断后升高一级模型。升级模型可直接放行，但必须落盘裁决理由、证据、被接受风险和产物 SHA256。

推荐命令顺序：

```powershell
python D:\DevTools\glm-pipeline\glm_call.py task-packet.md -o answer.md
python D:\DevTools\glm-pipeline\api_gate.py answer.md
python D:\DevTools\glm-pipeline\static_gate.py answer.md
python D:\DevTools\glm-pipeline\rewrite_detector.py answer.md
python D:\DevTools\glm-pipeline\parse_files.py answer.md
# 上一条只暂存；从输出取得 STAGE_DIR\manifest.json
# 到批次节点后，隔离的 gpt-5.6-luna 读取本批任务卡、候选产物、manifest 与最小充分依赖，输出 review.md
# 主编排逐条完成 review.md 的裁决与证据
python D:\DevTools\glm-pipeline\review_check.py review.md --artifact STAGE_DIR\manifest.json
python D:\DevTools\glm-pipeline\parse_files.py --apply STAGE_DIR
```

规则：

- `parse_files.py` 默认仅允许 `Assets/`；确需 `Packages/`、`ProjectSettings/` 或 `docs/` 时必须显式增加 `--allow-prefix`。
- 暂存记录每个目标的基线哈希；任一文件在审查期间改变，整批拒绝 apply。
- 复核不设疑点数量 KPI；每条真实疑点使用 `LUNA-H1` 等唯一编号。裸“证实”不得过闸，须修复并给证据；未关闭阻断项必须明确为“无”。
- 默认由独立 `gpt-5.6-luna` 分批审核。审核隔离采用最小充分上下文，可按需读取当前批次依赖的接口、配置和全局约束；Sol 可查原报告。任务卡、候选产物、审核报告、修复后产物都必须记录 SHA256，修复后不得沿用旧产物的放行结论。
- `glm_call.py` 遇 `max_tokens` 会保存 `.partial` 并返回失败，截断输出禁止进入门禁。
- 所有代码文件按物理行计数（含空行与注释）不得超过 300；超限先拆分职责。

## 5. 验收矩阵

| 产出 | 必要证据 | 验收 |
|---|---|---|
| Sim/View 代码 | 编译、EditMode 断言、相关回归 | TestQA → 主编排 |
| AI 代码交付 | 暂存清单哈希、模型复核、逐条裁决、零阻断 | Reviewer → 主编排 |
| AI/生产/时序改动 | 上述证据 + 长线冒烟；检查日志 `error CS` 与测试总数 | 主编排 |
| 画面/渲染 | 原图、程序化读数、视觉模型风险清单 | VisualQA 辅助 → 制作人 |
| 交互流程 | Play 黑盒输入→输出与录屏/日志 | 主编排操作 → 制作人 |
| 资产生成 | 文件完整、可导入、材质/骨架/动画检查 | 程序主程 → 制作人 |

测试全绿只证明已覆盖契约没有失败，不自动证明无回归、好看或好玩。验收完成后再创建里程碑提交；测试未绿的工作可保留在未提交工作树或显式 WIP 分支，但不得伪装成已验收基线。

每项必须独立标记三态：`工程验收`（门禁/编译/测试）、`实机验收`（真实输入与运行证据）、`制作人验收`（审美、手感和产品取舍）。未适用写“不适用”，未执行写“待验”，前一态不得替代后一态。

## 6. 视觉与付费媒体红线

- 视觉先按执行端分流：ZCode 优先套餐内置 4.5V；Codex 优先原生 GPT 视觉，TokenHub `glm-5v-turbo` 只作批量预检、补充或交叉验证。所有视觉记录统一包含执行端、模型、输入图 SHA256、原始输出和复核结论，跨端证据不得混写。
- 精确数值、小文字、数量和坐标优先程序化测量；视觉模型必须声明不确定处。
- 生图结果必须先展示给制作人并获明确确认，才允许进入 3D。
- 3D 模型入库/修正后必须再次获制作人确认，才允许生成动作。
- 当前 Codex/TokenHub 3D 适配器尚未端到端跑通，约 ¥5/次；按制作人决定，等真实项目需要时顺带验证，禁止为了“连通性”单独消费。

## 7. DeepSeek 成本窗

- 北京时间每天 `[12:00, 18:00)` 禁止所有 DeepSeek API 调用；12:00 整开始禁用，18:00 整恢复。
- 禁用窗内由 Terra 执行、Luna 审核、Sol 抽查，不做 DeepSeek 探活。
- 2026-09-10 起允许时段的 V4 Flash 也只执行边界清晰的低中风险任务；审核仍由 Luna，不得因时段开放扩大权限。
- `deepseek_review.py` 内置时间硬拦截；台账必须记录实际执行模型和费用。

## 8. 交接与台账

专家之间不直接辩论。编排层传递任务包、产物和证据索引，不复制无关历史。每个子模块完成、返工或升级时立即记账并建立可恢复检查点；每个安全小块完成后还必须在同一收口回合把状态、证据、批次进度及未提交/已提交状态同步到 `../PROJECT_STATE.md`，不能只写 `PROJECT_BRIEF.md`、验收索引或机器台账。审核账额外记录批次、子模块编号、轮次、原提交模型、拦截项及升级裁决。最少记录任务 ID、实际模型、基线提交、任务/输入/候选产物/审核/修复后产物哈希、停止原因、接口用量/费用、门禁、三态验收、未关闭阻断项和制作人待确认项。格式见 `TASK_LEDGER.md`。

排查 Sim 异常时优先写一次性诊断脚本，一次打全数量/位置/状态/队列/资源池；确认事实后删除诊断工具。假设只能指导取证，不能替代证据。
