# 视觉模型标定规程

> 本规程用于 **Codex 端**原生 GPT 视觉和 TokenHub `glm-5v-turbo`：GPT 是默认视觉入口，GLM-5V 只作批量预检、补充或交叉验证；两者完成项目缺陷集标定前均无独立放行权。**ZCode 端**内置 4.5V 已经过实战验证、准确度高，仍为 ZCode 默认 VisualQA；服务版本或图像预处理改变时再做回归标定。

## 1. 标定目标

不是测试“能否描述图片”，而是验证它能否稳定发现项目会真实发生的缺陷，并控制误报。结论必须与人眼金标和程序化测量对照。

## 2. 最小缺陷集

至少覆盖下列类别，每类准备一个已知正常样本和一个已知缺陷样本：

1. 模型碎面、肢体扭曲、穿模与武器黏连。
2. 构图裁切、相机过远、主体不可辨。
3. 过曝、过暗、颜色/阵营识别错误。
4. UI 遮挡、按钮缺失、层级重叠。
5. 小文字/精确数值（只测试它是否主动声明不确定；最终以程序化读数裁决）。
6. 动画姿态与静态站桩区分；动画必须使用成品模型渲染或录屏帧。

## 3. 固定提问

每张图分别回答：

- 画面基本逻辑是否成立？列出可定位的客观异常。
- 是否存在糊、过曝/过暗、构图、颜色、模型破损或 UI 风险？逐项回答并说明可见证据。
- 哪些结论无法从当前分辨率可靠判断？禁止猜精确数值。

不得在提示里泄露样本“正常/缺陷”标签。

## 4. 记录与准入

统一记录执行端、样本 SHA256、原图尺寸、模型名/日期、问题、原始回答、人眼金标、程序化证据、复核结论、命中/漏报/误报。高危缺陷（碎面、穿模、关键 UI 缺失）出现漏报即不授予单路放行权。

Codex 原生 GPT 视觉或 `glm-5v-turbo` 分别标定通过后，才可扩大对应入口的视觉验收权限；审美和手感仍由制作人终审。模型升级、服务商变更、图像预处理变化后需重标定。跨端报告必须标注 `ZCode/4.5V`、`Codex/GPT` 或 `Codex/glm-5v-turbo`，禁止只写“视觉模型通过”。
