# 铁幕:前线 · 专家团花名册(ROSTER)

> 架构:每个专家 = 一个大模型 + 角色卡(系统提示词)。角色卡见 `agents/`,编排协议见 `PROTOCOL.md`。
> 当前阶段:专家团主体已建,**模型接入位待用户提供 API 后填入**。

## 三层架构

```
┌─────────────────────────────────────────────┐
│ 总监层(决策权,不由模型担任)                      │
│  制作人 Producer         = 用户(终审:审美/手感/拍板) │
│  技术总监 Director       = 编排模型(GLM-5.3 兼任) │
└─────────────────────────────────────────────┘
            │ 拆解/派单 ↓  ↑ 验收上报
┌─────────────────────────────────────────────┐
│ 专家层(执行,每个=模型+角色卡)                     │
│  主策划 GameDesigner      ← 模型待接入           │
│  美术总监 ArtDirector     ← 图像模型待接入        │
│  资产生成 AssetGenerator  ← 3D 模型待接入         │
│  程序主程 LeadProgrammer  ← GLM-5.3(已接入)     │
│  音效师 AudioDesigner     ← 模型待接入(或程序化)   │
└─────────────────────────────────────────────┘
            │ 产出 ↓  ↑ 问题回馈
┌─────────────────────────────────────────────┐
│ 验收层(只查对错,不做创作)                        │
│  视觉验收 VisualQA       ← hy-vision-2.0(TokenHub) │
│  测试验收 TestQA         ← GLM-5.3 + 188 断言体系 │
│  逻辑挑刺 LogicAuditor   ← deepseek-v4-pro(已接入) │
└─────────────────────────────────────────────┘
```

## 接入一个模型需要什么(用户提供)

1. 平台名 + API 文档链接
2. API key(放本地配置文件,不回显;与现有 GLM key 同位置管理)
3. 额度/计费限制
4. 之后由技术总监封装调用脚本(`D:\DevTools\team-pipeline\<expert>_call.py`,仿 `glm_call.py` 模式:读提示词文件→调 API→存输出)

## 各专家职责一句话

| 专家 | 职责一句话 |
|---|---|
| 制作人 | 拍板:目标、风格、手感、一切模型不可裁决的取舍 |
| 技术总监 | 拆解需求→派单给对应专家→分析失败原因→组织验收 |
| 主策划 | 玩法结构/关卡节奏/机制设计文档(不写代码) |
| 美术总监 | 风格规范:参考图/色板/材质/光照基准(供资产生成与落地对照) |
| 资产生成 | 按风格规范批量出 3D/2D 资产文件 |
| 程序主程 | 全部代码与数值实现(Sim/View/Tests) |
| 音效师 | 音效资产/程序化音频 |
| 视觉验收 | 截图/画面按规范做"一致性与正确性"检查,不做审美裁决 |
| 测试验收 | 断言设计与失败分析(输入对输出对) |
