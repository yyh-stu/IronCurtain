# 模型路由与升级规则

> 目标：先用脚本，再优先消耗已有套餐能力；只在效果确有收益时使用按量 API。模型事实状态以 `../PROJECT_BRIEF.md` 为准。

## 1. 总顺序

1. `rg`、Git、哈希、编译器、测试、像素统计等本地证据。
2. `gpt-5.6-sol` 总编排：大模块范围、跨文档冲突、公共契约授权和最终技术裁决。
3. `gpt-5.6-terra` 执行编排：拆分与验收子模块，亲自处理核心状态机、公共接口和中高风险工程。
4. 2026-09-10 起，边界清晰的低中风险任务可交 `deepseek-v4-flash`；每日北京时间 `[12:00, 18:00)` 禁用，除非制作人后来明确解除。
5. `gpt-5.6-luna` 在每 5 个子模块或大模块尾批节点使用隔离上下文分批只读审核；任务卡、产物、报告和修复后产物均哈希绑定。

本架构自 2026-09-09 起生效，不再视为 GLM 额度耗尽时的临时覆盖。小而同质的任务可合并模块负责人和执行 Agent 岗位，审核员不得与执行岗位合并。2026-09-09 当天不实际调用 DeepSeek V4 Flash。

总编排对项目结果和实际效果负责，模型成本与 token 优化服从这一目标；禁止为了省 token 降低证据完整性，也禁止重复读取、无收益调用和冗余表达。面向用户一句能说清楚的事不用两句。

## 2. 文本/代码默认路由

| 任务 | 默认执行 | 升级条件 |
|---|---|---|
| 文件定位、差异、哈希、清单、格式转换 | 本地脚本 | 脚本无法表达语义时交 Terra |
| 长文抽取、日志归类、机械文档 | 本地脚本；2026-09-10 起允许时段可用 Flash | 拍板语义冲突交 Terra/Sol |
| 小范围低中风险代码 | 2026-09-10 起允许时段的 deepseek-v4-flash | 共享状态、状态机、公共 API 交 Terra |
| 常规 Unity C#、测试、联调 | gpt-5.6-terra | 跨大模块或产品取舍交 Sol/制作人 |
| 核心状态机、公共接口 | gpt-5.6-terra | 必须有 Sol 任务卡显式授权 |
| 隔离分批审核 | gpt-5.6-luna | 阻断返原源码提交模型；同批三轮拦截后升高一级裁决 |
| 范围、架构、冲突、最终技术决定 | gpt-5.6-sol | 产品取舍交制作人 |

审核独立性由隔离上下文、只读权限和哈希绑定保证，不以厂商不同替代证据。Luna 可读取当前任务所需接口、配置和全局约束；Sol 可直接检查原始报告。

## 3. DeepSeek 时间与成本硬规则

- 时区：北京时间（UTC+8）。
- 禁用窗：每天 `[12:00, 18:00)`，即 12:00:00 起禁用，18:00:00 恢复。
- 2026-09-09 不实际调用；最早 2026-09-10 试用。
- 禁用窗内不调用、不做探活、不因工作流默认步骤破例；由 Terra 执行、Luna 审核。
- 允许时段也仅授权 V4 Flash 执行边界清晰的低中风险任务；不得处理核心状态机、公共接口或高风险逻辑。
- `deepseek_review.py` 已内置时间硬拦截；其他调用入口由主编排遵守同一规则。

## 4. 视觉按执行端路由

## 6. 风险与调用形态

- 低风险：文档措辞、只读摘要、单文件局部且有直接测试。本地脚本优先；Flash 按日期和时段授权。
- 中风险：多文件、View 接线、测试基建。Terra 实现/验收，Luna 隔离审核；公共接口仍只由 Terra。
- 高风险：Sim 状态机、时序、结算、经济、存档、批量资产写入、付费外部调用。Terra 实现，Sol 授权/抽查，Luna 审核。
- 短单轮任务优先直接 runner，避免完整 Codex 会话固定上下文开销；代码修改仍须由 `build_task_packet.py` 附完整目标源码。
- 输出截断、伪造 API 或越权改动：立即停止继续消耗；审核阻断则由原提交模型闭环，同批连续三轮后升高一级模型，升级模型可留证直接放行。

## 7. 最小交接

每个子模块完成、返工或升级时立即记录任务 ID、角色/模型、基线提交、任务/输入/候选产物/审核/修复后产物哈希、停止原因、用量/费用、门禁/测试、三态验收、可恢复检查点和未关闭阻断项。审核另记批次、子模块号、轮次、原提交模型与升级裁决。Sol 默认读摘要与证据索引，必要时可打开 Luna 原报告。
