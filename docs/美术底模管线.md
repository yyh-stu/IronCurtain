```

   └─ 有机(怪物躯体/毛发/披风/面部):Seedream 生图 →【红线:人工复核】→ hy-3d-3.0 粗模 → 导入 Blender 清理/作参考重做

③ 四视图渲染(前/侧/顶/透视)→ 4.5v 预检客观项(穿模/法线/比例/糊)→ 用户人工复核调优
```

## 2. AI 分工与理由(「生图 AI 还是建模 AI」的答案)

| 环节 | 用什么 | 为什么 |
|---|---|---|
| 风格/概念定稿 | Seedream 生图(2D) | 便宜快、一次几十张候选;定风格最快手段;纯生图不触发 3D 红线 |
| 硬表面底模 | GLM-5.3 写 Blender bpy 脚本 | 修改器非破坏、拓扑干净、参数可调 = 人工调优最友好;免费无限迭代 |
| 有机粗模 | 生图→hy-3d-3.0 | 脚本建模做有机形态上限低;图生 3D 负责剪影/比例,人再清理 |
| 建模 AI 直出 3D | 备用(占位/快速原型) | 拓扑三角面糊、UV 乱、几乎改不动——不适合「要人工调优的底模」 |

结论:底模环节「建模 AI 直出」反而不优;**最优组合 = 生图定风格 + 脚本/图生3D 分流出底模**。

## 3. 人工复核调优规范(用户新规)

- 每个底模入库前必经用户过目(四视图渲染图或亲手打开 Blender);用户调优或判定「无需修改」放行。
- 放行结论写入 commit message:`模型名 + 复核:已调优/无需修改`。
- 4.5v 预检先行,只报客观项(穿模/法线翻转/比例崩坏/糊);主观审美终审永远归用户。

## 4. 入库标准

- **工作区(全程留痕)**:`D:\DevTools\美术资产仓库\`(跨项目资源库)——台账外三类:01_概念图 / 02_3D建模 / 03_3D动作(均按角色分子目录);00_台账 内含主流水账、去向登记/、过程存档/(脚本/渲染);复核结论走台账列(已调优/无需修改/驳回重做),失败也登记。仓库 README 为留痕规范权威。
- 最终入库路径:`Assets/Resources/Models/Gen/<类别>/<名称>_v<N>.fbx`(全项目统一 FBX;glb 仅当管线特定需求)
- 单位:1 Blender 单位 = 1 米(与 Sim 世界米制一致);原点=脚底中心;朝向约定随首模验证固定并回写本节
- 面数预算(演示级,待首模校准):英雄 <8k tris、建筑 <3k tris
- 材质:Blender 节点不导出;Unity 侧 URP 纯色/简单 Lit 重建,配色表随模型入库
- 入库 = git commit(全绿即 commit 惯例),模型 + .meta 一起提交

## 5. 红线与门禁

- TokenHub「生图→生3D」人工复核红线不变:生图结果必须用户确认后才提交 3D 任务。
- Blender 脚本底模属程序化资产,不触发上述红线;但本节第 3 条的人工复核是用户新规,每模必过。
- 视觉验收凡涉「看」必走 4.5v(Blender 渲染图直接喂,原图分辨率)。
- GLM 的 bpy 脚本同样跑门禁思路:无头执行报错即回喂修复(≤3 轮),脚本文件单文件 ≤300 行、命名与注释规范照 C# 惯例。
