## 4. 三个返工项与落地规则

### VR01：护盾必须在同一个血槽内

改动范围优先限定 EntityView.Hud.cs 和对应测试。不改 Hp/Shield 的 Sim 结算。

- 固定同一外框、同一高度和锚点；生命用阵营色，护盾用灰白色，护盾紧接可见生命段。不得独立伸到外框左/右侧、上/下方，不靠把血条整体加长隐藏错误。
- 默认布局建议：H=clamp(Hp,0,MaxHp)，S=max(Shield,0)，D=max(MaxHp,H+S)。生命长度 W*H/D，护盾长度 W*S/D，剩余为空槽。MaxHp<=0 安全隐藏。此为本项目建议实现，不声称精确复刻英雄联盟所有规则。
- 两段统一从同一条屏幕可读的起点排列。示例：MaxHp=100,H=100,S=50 → 生命占2/3、盾占1/3；H=60,S=20 → 60%生命+20%盾+20%空槽；S=0 → 恢复正常生命比例；超额盾也不得越框。
- SetHp 与 UpdateShield 应共用一次布局结果，避免一个方法写完后另一个又用旧分母覆盖。刻度若仍表示10点生命，就按同一 D 换算；别把非满血误画成满血。
- 先验证摄像机投影方向，不能用 local +X 的“右侧”注释代替屏幕取证；背板、刻度、两段填充须无镜像错序或 Z-fighting。
- 必交画面：满血有盾、残血有盾、零盾、超额盾、破盾后、蓝红两方与两个镜头缩放；所有填充顶点在外框内部。保留正常生命扣减和阵营识别。

### VR02：磐石盾牌贴臂竖持

- 标定盾内侧把手/绑带点、盾外表面法线、盾上方向，以及左掌心和左前臂支撑点。使用每资产/每英雄可持久化配置；不再只扫最长轴和 RollDeg。
- 先校准同一个已求值的待机姿态，再看行走和完整攻击周期。中立持盾时盾主体近竖直、外面朝外、内侧贴前臂；允许真实防御/攻击动作产生合理倾斜，不要求所有帧像钉在世界里。
- 如左臂在共享攻击动作中把盾带成托盘，应修磐石局部持盾姿态/上肢动画层，而不是每帧把盾硬锁世界竖直或只转盾不管手臂。
- 先证实现有骨架可支持哪些关节。必要时只调整对应手/前臂姿态或局部资源；不全量重生成角色。不得损害右手刀的握持。
- 验收：正常游戏视角不再呈现明显横躺/翻面；手部近景能看清把手/绑带和手臂的承托关系；待机、走、转身、攻击进入/接触/收招持续跟手，不穿胸、不脱臂。

### VR03：镇岳确实握住锤柄，不是锤跟着张开的手漂移

- 同时处理“锤柄落点”和“握持手形”。定义锤柄真实三维 Grip、掌心偏移、杆方向；调局部位置/旋转后，手指必须围住杆体，不能只把杆穿进腕骨。
- 有可用手指骨和蒙皮时：做持锤手姿态，并保证不会被 Animator 下一帧覆盖。无可用手指骨/权重时：提交证据，采用局部手部网格姿态修正或最小补骨/权重处理；现有技术权限可做的本地修复不再当“等用户选金样”。需付费生成、整模重做或明显风格改变才另请制作人决定。
- 单手持锤可作为现有资产的最小落地默认；若现有攻击姿态实际需要双手支撑，就给副手明确的第二握点，只在合理接触窗口约束。不要形成“武器跟双手、双手又互相追武器”的约束循环。
- 不强制锤子永远竖着；重心、柄向可随动作变化。判定重点是手握住、腕姿自然、头部不穿身、走动转向和挥击时不滑柄/漂浮。
- 先把镇岳修成合格样板，再提炼通用配置；不要在已明显失败的握持图里让制作人选一张当“标准答案”。
